基础概念#

Job#

所有DeviceManagerService的Api调用，都会在DeviceManagerService中，产生一个与之对应的Job，用于描述该次调用的具体接口信息和调用参数。

Call#

在DeviceManagerService的具体业务的实现，都是通过AIDL中的接口 Call 进行调用，在 Call 的参数中用于指定调用的具体Api和Api参数。

String call(String jobCat, String jobType, String jobParams , String callParams);

jobCat#

需要调用Api的大类别，例如 wifiJobs ， packageJobs 等

jobType#

需要调用的具体Api，例如 TakeScreenShot 等

jobParams#

调用的Api参数

callParams#

该次 Call 的参数，不同于jobParams，它作用于该次调用的属性，目前版本中，它的定义如下：

class CallParams {
    var delay = 0
    var dependencyJobId = -1
}

delay ：调用的延迟，单位ms。

dependencyJobId ：依赖JobId，当指定的Job成功完成后，该Job才会被执行，否则会被取消。

CallResult#

Call 的返回值是 CallResult 的 Json序列化字符串，用于表示这次 Call 的调用结果，它具体构成如下:

class CallResult {
    var errorDescription: String? = null
    var jobID: Int = 0
}

jobID#

当一个 Call 被DeviceManagerService成功响应时，会生成一个与该 Call 对应的 大于0的jobID ，当一个Call失败时，会生成一个 小于0的JobID 。

errorDescription#

当 Call 调用失败时，用于返回失败原因。

需要注意的是， CallResult 不代表这次Api的完成结果，只是表示这次 Call 的结果，调用结果通过 Api Result 返回给调用者。

Api Result#

DeviceManagerService所有的Api都是异步处理的，它的结果通过 IDeviceManagerResultListener ：

interface IDeviceManagerResultListener {
    void onResult(int jobId, String result);
}

返回给调用者，当一个Job的完成，会在调用者的进程触发一次该回调。

jobID : 该结果对应的 Call 的 jobId 。

result: Api调用结果，我们称之为 ApiResult ,它通过AIDL接口：

void setDeviceManagerResultListener(IDeviceManagerResultListener listener);

进行设置，每一个进程只能设置一个一个有效的ResultListener，每次调用会覆盖之前的设置。

Job完成时，如果没有设置Listener、或者Listener被释放或者调用者进程被释放，则不会收到这个回调，但是，该Job依然会正常执行并产生结果。

ApiResult 对应的数据结构如下：

class ApiFinishedResult {
    var jobId = 0
    var returnCode = 0
    var result: String? = null
    var error: String? = null
}

它是该结构的Json序列化字符串。

jobId#

该结果对应的 Call 的 jobId 。

returnCode#

Api执行结果，0：成功执行 ，1：任务被取消，2：调用错误。

result#

Api执行结果的Json序列化字符串，对应的是 Api文档中的Result 定义。

error#

当Api调用失败时，用于显示错误原因。

Event#

除了标准的 ApiResult 以外，我们提供了 Event 用于处理一些长期或者持续性的回调，例如，在扫描蓝牙或者Wifi时，由于扫描结果是持续性的，会触发多次回调，我们通过 Event 回调来进行结果的返回。

又如，监听电池变化事件，由于电池变化是个长时间的持续变化的事件，因此，调用对应的Api会激活应用的 Event 监听，并且持续通过 EventListener 进行事件上报。

通常来说，我们不显式地提供具体某个事件的注册接口，通常事件的注册是与接口相关的，在API文档中会标注每个API相关的Event，其中，大部分Event监听会在API完成后自动释放。

与Result类似，它使用AIDL接口：

void setDeviceManagerEventListener(IDeviceManagerEventListener listener);

进行设置。

其中， IDeviceManagerEventListener 如下所示：

interface IDeviceManagerEventListener {
    void onEvent(String eventType, String eventInfo);
}

eventType#

事件的名称， Event 的具体String值在本文档的 Event 下可以进行查看。

eventInfo#

事件的具体信息的Json序列化，根据Event类型变化，具体数据结构可以在本文档Event下进行查看。

与 ResultListener 类似， EventListener 每个应用只能进行一个有效的回调注册。

同时，它还具有以下特点：

  1. Event 大多是与某个Api调用所绑定的，在Api文档中，可以看到每个Api所关联的 Event 事件。

  2. 大多 EventListener 会在Api调用完成后被释放。

  3. 如果多个应用监听了某 Event 的监听，则这些应用都会收到 Event 回调。

  4. 与Api类似， Event 的监听同样有权限，只有达到该权限的DeviceManagerService调用者才会监听到对应的 Event。
