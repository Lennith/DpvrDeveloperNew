Basic Concepts#

Job#

All API calls to DeviceManagerService will generate a corresponding Job in DeviceManagerService, which describes the specific interface information and call parameters of this call.

Call#

The specific business implementation of DeviceManagerService is called through the interface Call in AIDL. The parameters of Call are used to specify the specific API and API parameters to be called.

String call(String jobCat, String jobType, String jobParams , String callParams);

jobCat#

The major category of the API to be called, such as wifiJobs, packageJobs, etc.

jobType#

The specific API to be called, such as TakeScreenShot, etc.

jobParams#

The parameters of the API to be called

callParams#

The parameters of this Call, different from jobParams, it affects the properties of this call. In the current version, its definition is as follows:

class CallParams {
    var delay = 0
    var dependencyJobId = -1
}

delay ：The delay of the call, in milliseconds.

dependencyJobId ：Dependent JobId. This Job will only be executed after the specified Job is successfully completed, otherwise it will be cancelled.

CallResult#

The return value of Call is the** Json serialized string **of CallResult, which represents the result of this` Call call. Its specific composition is as follows:

class CallResult {
    var errorDescription: String? = null
    var jobID: Int = 0
}

jobID#

When a Call is successfully responded by DeviceManagerService, a jobID greater than 0 corresponding to this Call will be generated. When a Call fails, a JobID less than 0 will be generated.

errorDescription#

When the Call call fails, it is used to return the cause of the failure.

It should be noted that, CallResult does not represent the completion result of this API, it only represents the result of this Call call. The call result is returned to the caller through Api Result .

Api Result#

All APIs of DeviceManagerService are processed asynchronously. Its result is returned to the caller through IDeviceManagerResultListener :

interface IDeviceManagerResultListener {
    void onResult(int jobId, String result);
}

When a Job is completed, this callback will be triggered once in the caller’s process.

jobID : The jobId of the Call corresponding to this result.

result: The result of the API call, which we call ApiResult. It is set through the AIDL interface:

void setDeviceManagerResultListener(IDeviceManagerResultListener listener);

Each process can only set one valid ResultListener, and each call will overwrite the previous setting.

When a Job is completed, if no Listener is set, or the Listener is released, or the caller process is released, this callback will not be received, but the Job will still be executed normally and produce results.

The data structure corresponding to ApiResult is as follows:

class ApiFinishedResult {
    var jobId = 0
    var returnCode = 0
    var result: String? = null
    var error: String? = null
}

It is the Json serialized string of this structure.

jobId#

The jobId of the Call corresponding to this result.

returnCode#

The execution result of the API, 0: successful execution, 1: task cancelled, 2: call error.

result#

The Json serialized string of the API execution result, which corresponds to the Result definition in the API document .

error#

When the API call fails, it is used to display the cause of the error.

Event#

In addition to the standard ApiResult, we provide Event to handle some long-term or continuous callbacks. For example, when scanning Bluetooth or Wifi, because the scanning result is continuous, it will trigger multiple callbacks, and we use Event callback to return the result.

For example, listening to battery change events, because battery changes are long-term continuous events, therefore, calling the corresponding API will activate the application’s Event listening, and continuously report events through EventListener.

Generally speaking, we do not explicitly provide a registration interface for a specific event. Usually, event registration is related to the interface. The API document will mark each API related event, most of which will be automatically released after the API is completed.

Similar to Result, it uses the AIDL interface:

void setDeviceManagerEventListener(IDeviceManagerEventListener listener);

to set.

The IDeviceManagerEventListener is as follows:

interface IDeviceManagerEventListener {
    void onEvent(String eventType, String eventInfo);
}

eventType#

The name of the event, the specific String value of Event can be viewed under Event in this document.

eventInfo#

The Json serialization of the specific information of the event, the specific data structure can be viewed under Event in this document according to the change of Event type.

Similar to ResultListener, each application can only register one valid callback for EventListener.

At the same time, it has the following characteristics:

  1. Most Events are bound to a certain API call. In the API document, you can see each API associated with the Event event.

  2. Most EventListeners will be released after the API call is completed.

  3. If multiple applications listen to a certain Event listening, these applications will all receive the Event callback.

  4. Similar to the API, the listening of Event also has permissions. Only the DeviceManagerService caller who has reached this permission will listen to the corresponding Event.
