Developer Recommendations¶

Rapid development¶

If you only need to use the built-in features of the RDC all-in-one device and do not plan to invest significant effort in developing the server, we offer two rapid development methods:

  1. Server Development Based on Communication Protocol: Developers can implement the communication protocol and develop server functionalities according to the communication protocol section. This method is more flexible when the client protocol is updated; developers only need to add corresponding communication processing for the new protocol to use the new RDC features.

  1. Based on RDC Library for Server-side Development : Developers can use the encapsulated interfaces provided by Dpvr, invoking RDC functionalities through the C# Dll loading method. Compared to protocol-based development, when the client is updated, you need to wait for the corresponding RDC library update to import new features.

Server development¶

If developers wish to fully self-develop the server, we recommend that developers implement the communication protocol and develop server functionalities according to the communication protocol section in this document.

Extended function development on headset¶

If you need to implement control functions that are not currently available in RDC, developers can develop client applications to implement these functions and use the RDC pass-through feature to send messages directly to the application via the RDC communication link to invoke these functions. The pass-through feature can be called through the AIDL interface provided by RDC (Native Android) or the DPVR DeviceManagerService interface.
