Practical guide

Build an RDC controller in C#

Connect one headset and receive its identity before sending a targeted command and checking the outcome.

Prerequisites

  • Prepare a Win64 .NET 7 development environment and the official RDC library or sample.
  • Prepare a supported headset on the LAN. USB/adb checks system packages; it is not the RDC transport.
01

Check headset services

The first query should return com.deepoon.eggchair. If missing, check the system version. The other packages are needed for video playback and automatic startup respectively. Check required packages before network setup; a PC DLL cannot add headset services.

adb shell pm list packages com.deepoon.eggchair
adb shell pm list packages com.dpvr.videoplayer
adb shell pm list packages com.dpvr.daemonservice
Read: Check headset services →
02

Configure network and server address

For an initial connection, enter the controller LAN IP and port and ensure it listens on a reachable address. AUTO FIND additionally requires server-side discovery, the same broadcast domain and allowed broadcasts. It overrides the manual address; an identical Wi-Fi name is insufficient.

Read: Configure network and server address →
03

Choose the matching C# library

Use the .NET 7 Win64 library and sample linked by the current documentation and reference namespace DPVR. Check the bundled-runtime option if .NET 7 Runtime is absent. Build successfully before proceeding; do not substitute an older same-named DLL.

Read: Choose the matching C# library →
04

Register callbacks before starting

Use this fragment inside an application referencing the official library and keep mServer alive. state=1 means connected after the headset reports its SN. Wait for SN/IP output before enabling commands. The default port is 10086 and must match the headset.

var mServer = new DPVR.DpvrRDCServer();
mServer.OnConnectStateChangedEvent += (client, state) =>
    System.Console.WriteLine($"state={state} SN={client.SN} IP={client.IP}");
mServer.OnMessageEvent += (client, message) =>
    System.Console.WriteLine($"SN={client.SN} from={message.fromPackage}: {message.content}");
mServer.Start();
Read: Register callbacks before starting →
05

Send one explicitly targeted command

This console fragment uses the same live mServer as the previous step. Enter the SN printed by the connection callback. Send the volume command only when a client is found with ConnectState=1. Pass an explicit single-client list so an omitted target cannot affect every device. Check the actual volume next.

System.Console.WriteLine("Enter the connected headset SN:");
var targetSerialNo = System.Console.ReadLine();
var client = string.IsNullOrWhiteSpace(targetSerialNo)
    ? null : mServer.GetClient(targetSerialNo);
if (client != null && client.ConnectState == 1)
{
    mServer.DeviceSetVolume(20,
        new System.Collections.Generic.List<DPVR.DpvrRDCServer.Client> { client });
}
Read: Send one explicitly targeted command →
06

Inspect status before expanding

Inspect SN, IP, ConnectState, battery and foreground application, confirm ongoing heartbeat updates, and check the actual volume on the test headset. These fields are not per-command acknowledgements. For disconnections, check addresses, ports and networking. HTTP content distribution additionally needs separately hosted files: RDC sends manifests and the headset DownloadService downloads them.
