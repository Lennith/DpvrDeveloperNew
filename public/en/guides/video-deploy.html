Resources / System Player Configuration
Practical guide

Play a chosen video when the headset player starts

Verify ordinary video playback on one headset first. Add authorization or bulk delivery only if your task requires it. This uses the system player, without building a Unity app.

1. Prepare the video and headset

DPVR lists P1 Max, P2, P1 Ultra 4K, P1 Pro 4K and P1 Pro for this resource. Start with a video that plays correctly on the device and identify its projection format. This example uses monoscopic 360° video; use videoModel: 0 for ordinary flat 2D video.

Connect a USB data cable and put demo.mp4 at the root of the headset shared storage. Its device path is /sdcard/demo.mp4. Open it manually on the headset and confirm the picture and sound first. If Windows cannot show storage, see the P1 Max MTP troubleshooting guide; that guide does not cover ADB authorization.

2. Create the complete configuration

Create a UTF-8 text file named AutoPlayDisposition.json and paste the complete JSON below. Check that the extension is not .json.txt.

{
  "isAutoPlay": 1,
  "videoPath": "/sdcard/demo.mp4",
  "videoModel": 16,
  "isSteadyOn": 0,
  "sleepTimes": 10,
  "lockView": false,
  "distance": 0,
  "isStartBeginning": 1,
  "showUI": 0
}

This example automatically plays demo.mp4 as monoscopic 360° video, turns off the display when removed, starts from the beginning and hides the playback menu. lockView=false keeps the image fixed in space. These are the online guide's example choices, not a claim about device defaults.

One unresolved range: distance applies only to flat modes 0, 1 and 4. The Chinese reference says -120 to 200, the English reference says 120 to 200, and both examples use 0. The exact range needs device or implementation verification; mode 16 in this example does not use it. The downloadable example uses lockView=true; both values are valid choices.

3. Put the file where the player reads it

Create AutoVideoPlay at the shared-storage root and place the JSON inside it. Keep the video at the path configured above. Do not use a Windows drive path in the JSON.

/sdcard/
├── demo.mp4
└── AutoVideoPlay/
    └── AutoPlayDisposition.json

Exit and restart the system player. The documentation says the configuration is read at startup; it does not promise live reload after editing.

4. Verify the first successful result

  1. Restart the player and confirm that it automatically opens the chosen video.
  2. Check the projection against the source video. If the picture is wrong, check videoModel before changing authorization or SDK settings.
  3. Check controls, display behavior when removed and restart behavior. For diagnosis, set showUI to 1 and restart the player again.
  4. If playback does not start, check the filename, JSON syntax, folder, videoPath and manual playback in that order. Keep the current configuration before changing another setting.

5. Add authorization or bulk delivery only when needed

Restrict devices or expiry: the video encryption tool creates matching .mp4, .dpve1 and .dpvei files. Deploy all three together and verify with a compatible DPVR player. Ordinary videos do not need encryption. GUI authorization edits re-encrypt; the CLI also offers an authorization-file-only update workflow.

Deploy offline to multiple headsets: use FILE or ZIP_UNPACK tasks in the TF deployment tool to place video and configuration at the locations above. Copy success is not playback verification. The tool's OTA_PACKAGE task only copies firmware packages; it does not run an upgrade.
