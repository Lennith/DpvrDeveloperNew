Usage Process#

  1. Import the DeviceManagerService unitypackage file into the project.

  2. Declare the application DeviceManager permission.

  3. Bind DeviceManagerService.

  4. Implement IDeviceManagerResultListener to listen for Api call results, implement IDeviceManagerEventListener to register event listening.

  5. Make DeviceManagerService API calls.

  6. Handle API call results.

  7. Handle events (Event).

0. unitypackage import#

Click here to download the unitypackage file, Open the unity project, select Assets->Import Package->Custom Package. After selecting the downloaded unitypackage, import it..

1. Permission Declaration#

Each interface of DpvrDeviceManagerService requires a specified permission to be called.

In the Api section of this document, each interface will be marked with the specific permission required.

The permissions of DpvrDeviceManagerService are divided into four types:

Permission Level

Need Authorization

Permission Description

NORMAL(0)

No

Normal permission

LAUNCHER(1)

Yes

Common Launcher permission, can get system settings

SYSTEM(2)

Yes

Common system permission, can change some system settings

ADMIN(3)

Yes

Highest permission, can call all interfaces

The caller of DeviceManagerService needs to add the following authorization information to the Application tag of their application AndroidManifest.xml to obtain the authorization of DeviceManangerService.

For application version authorization:

<meta-data android:name="DeviceManagerKey" android:value="YOUR_KEY_HERE"></meta-data>

Using this method of authorization, the current application package name and version number will be authorized, and this version of the application can run on all devices that support DeviceManangerService.

For specified channel firmware authorization:

<meta-data android:name="DeviceManagerPlatformKey" android:value="YOUR_KEY_HERE"></meta-data>

Using this method of authorization, the application package name will be authorized on the specified custom channel firmware, without checking the version number.

When both authorization methods exist at the same time, the highest permission that can be obtained will be used on the corresponding system.

Currently, you need to contact DPVR technical support to obtain DeviceManagerKey above NORMAL.

1. Bind DeviceManagerSerivce#

Just like a standard AIDL call, first we need to bind DeviceManagerSerice.

public static void Bind()
{
    AndroidJavaClass jc = new AndroidJavaClass(unityPlayerClass);
    AndroidJavaObject activity = jc.GetStatic<AndroidJavaObject>("currentActivity");
    deviceManager = new AndroidJavaObject("com.dpvr.devicemanagerclientjar.DeviceManagerBindMan", activity);
    SetCallbacks();
    deviceManager.Call("SetBind");
}

3. Register API call callback and Event callback.#

Implement DeviceManagerBindMan$OnDeviceManagerResult, DeviceManagerBindMan$OnDeviceManagerEventResult to handle Api call callbacks.

private static void OnResult(int jobId, string result)
{
    Debug.LogFormat("onResult: {0}  {1}", jobId, result);
}

private static void OnEvent(string eventType,string eventInfo)
{
    Debug.LogFormat("onEvent: {0}  {1}", eventType, eventInfo);
}

public delegate void OnDeviceManagerResult(int id, string result);

public class OnDeviceManagerResultListener : AndroidJavaProxy
{
    OnDeviceManagerResult _handler;
    public OnDeviceManagerResultListener(OnDeviceManagerResult handler) : base("com.dpvr.devicemanagerclientjar.DeviceManagerBindMan$OnDeviceManagerResult")
    {
        _handler = handler;
    }
    void OnDeviceManager(int id, string result)
    {
        _handler(id, result);
    }
}

public delegate void OnDeviceManagerEvent(string eventType, string eventInfo);

public class OnDeviceManagerEventListener : AndroidJavaProxy
{
    OnDeviceManagerEvent _handler;
    public OnDeviceManagerEventListener(OnDeviceManagerEvent handler) : base("com.dpvr.devicemanagerclientjar.DeviceManagerBindMan$OnDeviceManagerEventResult")
    {
        _handler = handler;
    }
    void OnDeviceManagerEvent(string eventType, string eventInfo)
    {
        _handler(eventType, eventInfo);
    }
}

public static void SetCallbacks()
{
    deviceManager.Call("SetDeviceManagerResultListener", new OnDeviceManagerResultListener(OnResult));
    deviceManager.Call("SetDeviceManagerEventListener", new OnDeviceManagerEventListener(OnEvent));
}

Please note that each application can only register one valid ResultListener and EventListener.

4. Make Api calls.#

The DeviceManager business API is called through the call interface.

String call(String jobCat, String jobType, String jobParams, String callParams) throws RemoteException;

The parameters are defined as follows:

jobCat

The category of the Api to be called, corresponding to the first level content in the Api document, such as “activityJobs”

jobType

The specific Api to be called, such as “GetRunningPackages”

jobParams

The parameters of the business Api to be called, which can be obtained from the Params in the corresponding Api document, and need to be Json serialized, can be empty.

callParams

The call parameters when calling this Api, such as delayed call, or this interface needs to depend on the completion of another Api call, can be empty.

The return value of this interface is:

class CallResult {
    /** When the call fails, it is used to indicate the cause of the error */
    var errorDescription: String? = null
    /** The task ID of this task call, corresponding to the jobID in ResultListener, when jobId<0, it means the call failed */
    var jobID: Int = 0
}

Serialized Json string.

Take packageJobs/CheckAppInstalled as an example, let’s see how to call the DeviceManagerService interface.

The documentation for this Api is as follows:

  1. Through the Api document, we know that the jobCat of the interface is packageJobs, and the jobType is CheckAppInstalled.

  2. Its Api call parameter is a String type packageName.

  3. Its call result only has one isExist attribute.

Therefore, we can make an interface call like this to check whether com.dpvr.devicemanager is installed:

private int checkIsAppInstalledJobId = 0;

public void CheckIsAppInstalled()
{
    string jobCat = "packageJobs";
    string jobType = "CheckAppInstalled";
    string jobParams = "{\"packageName\":\"com.dvpr.devicemanager\"}";
    string callParama = "{\"delay\":2000}";
    string ret = deviceManager.Call<string>("CallInterface", jobCat, jobType, jobParams, callParams);
    JsonData result = JsonMapper.ToObject(ret);
    if (result["jobID"] < 0)
    {
        Debug.LogFormat("Job error, for reason {0}", result["errorDescription"];
    } else {
        checkIsAppInstalledJobId = result["jobID"];
    }
}

Here, we parsed the CallResult and put the id of this task in checkIsAppInstalledJobId. When the call fails, we print its reason.

5. Handle Api call results.#

Since the DeviceManagerService API is all asynchronous, therefore, after the asynchronous completion, it will trigger the DeviceManagerBindMan$OnDeviceManagerEventResult interface registered in DeviceManagerSerice

private static void OnResult(int jobId, string result)
{
    Debug.LogFormat("onResult: {0}  {1}", jobId, result);
}

Where the result is

class ApiFinishedResult {
    /** The completed jobId */
    var jobId = 0
    /** Completion status, 0 call succeeded, -1 the task was cancelled, -2 failed */
    var returnCode = 0
    /** Api call result, determined by the specific Api called, corresponding to the Result in the Api document */
    var result: String? = null
    /** When the task fails, record the reason for the failure */
    var error: String? = null
}

The serialized result.

Here, we still use the example in the previous text to process its Api call result. Here, we print it

private static void OnResult(int jobId, string result)
{

}

6. Handling events (Event).#

When an Event is triggered, it will trigger the DeviceManagerBindMan$OnDeviceManagerEventResult interface registered in DeviceManagerSerice

private static void OnEvent(string eventType,string eventInfo)
{
    Debug.LogFormat("onEvent: {0}  {1}", eventType, eventInfo);
}

The definitions of eventType and eventInfo can be viewed in Events

Generally speaking, we do not explicitly provide a registration interface for a specific event. Usually, the registration of events is related to the interface. Each API-related Event will be marked in the API document, where most Event listeners will be automatically released after the API is completed.

ere, suppose we want to listen to the WIFI_SCAN_RESULT event and output the result, it can be implemented through the following code
