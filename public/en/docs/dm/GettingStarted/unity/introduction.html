Basic Concepts#

Job#

All Api calls of DeviceManagerService will generate a corresponding Job in DeviceManagerService, which is used to describe the specific interface information and call parameters of this call.

Call#

The specific business implementation of DeviceManagerService is called through the interface call in the aar package. The parameters in call are used to specify the specific Api and Api parameters to be called.

String call(String jobCat, String jobType, String jobParams, String callParams) throws RemoteException;

jobCat#

The major category of the Api to be called, such as wifiJobs , packageJobs etc.

jobType#

The specific Api to be called, such as TakeScreenShot etc.

jobParams#

The parameters of the Api to be called

callParams#

The parameters of this callParams, different from jobParams, it acts on the attributes of this call. In the current version, its definition is as follows:`

class CallParams {
    var delay = 0
    var dependencyJobId = -1
}

delay ：The delay of the call, in milliseconds.

dependencyJobId ：Dependent JobId, this Job will only be executed after the specified Job is successfully completed, otherwise it will be cancelled.

CallResult#

The return value of Call is the Json serialized string of CallResult, which is used to represent the result of this Call call. Its specific composition is as follows:

class CallResult {
    var errorDescription: String? = null
    var jobID: Int = 0
}

jobID#

When a Call is successfully responded by DeviceManagerService, a jobID greater than 0 corresponding to this Call will be generated. When a Call fails, a JobID less than 0 will be generated.

errorDescription#

When the Call call fails, it is used to return the cause of the failure.

Please note that, CallResult does not represent the completion result of this Api, it just represents the result of this Call, the call result is returned to the caller through Api Result.

Api Result#

All Apis of DeviceManagerService are processed asynchronously. Its result is returned to the caller through DeviceManagerBindMan$OnDeviceManagerResult:

public interface OnDeviceManagerResult {
    void OnDeviceManager(int jobId, String result);
}

When a Job is completed, this callback will be triggered once in the caller’s process.

jobID : The jobId of the Call corresponding to this result.

result: Api call result, we call it ApiResult.

It is set through the interface in the AAR package:

void setDeviceManagerResultListener(IDeviceManagerResultListener listener) throws RemoteException {};

Each process can only set one valid ResultListener, and each call will overwrite the previous setting.

When a Job is completed, if no Listener is set, or the Listener is released, or the caller process is released, this callback will not be received, but the Job will still be executed normally and produce results.

class ApiFinishedResult {
    var jobId = 0
    var returnCode = 0
    var result: String? = null
    var error: String? = null
}

The Json serialized string.

jobId#

The jobId of the Call corresponding to this result.

returnCode#

Api execution result, 0: successful execution, 1: task cancelled, 2: call error.

result#

The Json serialized string of the Api execution result, corresponding to the Result definition in the **Api document**.

error#

When the Api call fails, it is used to display the cause of the error.

Event#

In addition to the standard ApiResult, we provide Event to handle some long-term or persistent callbacks. For example, when scanning Bluetooth or Wifi, because the scanning result is persistent, it will trigger multiple callbacks, and we use Event callback to return the result.

Similarly, listening to battery change events, because battery change is a long-term continuous change event, therefore, calling the corresponding Api will activate the application’s Event listening, and continuously report events through EventListener.

Similar to Result, it uses the interface in the AAR package:

void setDeviceManagerEventListener(IDeviceManagerEventListener listener) throws RemoteException;

For setting.

Among them, IDeviceManagerEventListener is as follows:

public interface IDeviceManagerEventListener extends IInterface {
    void onEvent(String eventType, String eventInfo) throws RemoteException;
}

eventType#

The name of the event, the specific String value of Event can be viewed in the Event section of this document.

eventInfo#

The Json serialization of the specific information of the event, the specific data structure can be viewed in the Event section of this document according to the change of the Event type.

Similar to ResultListener, EventListener can only register one valid callback for each application.

At the same time, it also has the following characteristics:

  1. Most Event are bound to a certain Api call. In the Api document, you can see the Event event associated with each Api.

  2. Most EventListener will be released after the Api call is completed.

  3. If multiple applications listen to the listening of a certain Event, these applications will all receive the Event callback.

  4. Similar to Api, Event listening also has permissions. Only the DeviceManagerService caller who reaches this permission will listen to the corresponding Event.
