Usage Process#

  1. Import DeviceManagerService AIDL file into the project.

  2. Declare application DeviceManager permissions.

  3. Bind DeviceManagerService.

  4. Implement IDeviceManagerResultListener to listen for Api call results, implement IDeviceManagerEventListener to register event listeners.

  5. Make DeviceManagerService API calls.

  6. Handle API call results.

  7. Handle events (Event).

0. AIDL Import#

Click here to download the AIDL file, Create a new AIDL folder in the project and copy the interface description file of DeviceManager to the path of the folder (as shown in the figure below), and then build.

1. Permission Declaration#

Each interface of DpvrDeviceManagerService requires specified permissions to be called.

In the Api section of this document, each interface will be marked with the specific permissions required.

There are four types of permissions for DpvrDeviceManagerService:

Permission Level

Requires

Authorization Permission Explanation

NORMAL(0)

No

Normal permissions

LAUNCHER(1)

Yes

Common Launcher permissions, can get system settings

SYSTEM(2)

Yes

Common system permissions, can change some system settings

ADMIN(3)

Yes

Highest permissions, can call all interfaces

The caller of DeviceManagerService needs to add the following authorization information to the Application tag of their application AndroidManifest.xml to obtain the authorization of DeviceManangerService.

For application version authorization:

<meta-data android:name="DeviceManagerKey" android:value="YOUR_KEY_HERE"></meta-data>

Using this method of authorization will authorize the current application package name and version number, and this version of the application can run on all devices that support DeviceManangerService.

For specified channel firmware authorization:

<meta-data android:name="DeviceManagerPlatformKey" android:value="YOUR_KEY_HERE"></meta-data>

Using this method of authorization will authorize the application package name on the specified custom channel firmware, without checking the version number.

When both types of authorization exist at the same time, the highest permission that can be obtained will be used on the corresponding system.

Currently, you need to contact DPVR’s technical support to obtain a DeviceManagerKey with NORMAL or higher permissions.

1. Bind DeviceManagerSerivce#

Just like a standard AIDL call, we first need to bind DeviceManagerSerice.

private var mServiceConnection: ServiceConnection = object : ServiceConnection {
    override fun onServiceConnected(componentName: ComponentName?, binder: IBinder?) {
        deviceManager = IDeviceManager.Stub.asInterface(binder)
        setCallbacks()
    }

    override fun onServiceDisconnected(p0: ComponentName?) {
        Log.d(TAG, "on service disconnected")
    }
}

private fun bind(){
    val intent = Intent("com.dpvr.devicemanager")
    intent.component = ComponentName("com.dpvr.devicemanager","com.dpvr.devicemanager.DeviceManagerService")
    bindService(intent, mServiceConnection, Service.BIND_AUTO_CREATE)
}

3. Register API call callback and Event callback.#

Implement IDeviceManagerResultListener and IDeviceManagerEventListener to handle Api call callbacks.

private val mResultListener: IDeviceManagerResultListener =
    object : IDeviceManagerResultListener.Stub() {
        override fun onResult(jobId: Int, result: String?) {
            Log.d(TAG, "on job done ${jobId}, result $result")
        }
    }

private val mEventListener: IDeviceManagerEventListener =
    object : IDeviceManagerEventListener.Stub(){
        override fun onEvent(eventType: String?, eventInfo: String?) {
            Log.d(TAG,"On event $eventType, $eventInfo")
        }
    }

private fun setCallbacks(){
    deviceManager!!.setDeviceManagerResultListener(mResultListener)
    deviceManager!!.setDeviceManagerEventListener(mEventListener)
}

It should be noted that each application can only register one valid ResultListener and EventListener.

4. Make Api calls.#

You can call the DeviceManager business API by calling the AIDL interface call.

String call(String jobCat, String jobType, String jobParams , String callParams);

The parameters are defined as follows:

jobCat

The category of the Api to be called, corresponding to the first level content in the Api document, such as “activityJobs”

jobType

The specific Api to be called, such as “GetRunningPackages”

jobParams

The parameters of the business Api to be called, which can be obtained from the Params in the corresponding Api document. This parameter needs to be Json serialized and can be empty.

callParams

The call parameters when calling this Api, such as delay call, or this interface needs to depend on the completion of another Api call, can be empty.

The return value of this interface is:

class CallResult {
    /** When the call fails, it is used to indicate the cause of the error */
    var errorDescription: String? = null
    /** The task ID of this task call, corresponding to the jobID in ResultListener, when jobId<0, it means the call failed */
    var jobID: Int = 0
}

The serialized Json string.

Take packageJobs/CheckAppInstalled as an example, let’s see how to call the DeviceManagerService interface.

The documentation for this Api is as follows:

  1. Through the Api document, we know that the jobCat of the interface is packageJobs, and the jobType is CheckAppInstalled.

  2. Its Api call parameter is a String type pacageName.

  3. Its call result only has one isExist attribute.

Therefore, we can make an interface call like this to check whether com.dpvr.devicemanager is installed:

var checkIsAppInstalledJobId = 0
class CallResult {
    var errorDescription: String? = null
    var jobID: Int = 0
}

fun checkIsAppInstalled(){
    val jobCat = "packageJobs"
    val jobType = "CheckAppInstalled"
    val jobParams = "{\"packageName\":\"com.dvpr.devicemanager\"}"
    val callParams = "{\"delay\":2000}"

    deviceManager!!.call(jobCat, jobType, jobParams, callParams).let {
        val result = Gson().fromJson(it,CallResult::class.java)
        if(result.jobID < 0){
            Log.e(TAG,"Job error , for reason ${result.errorDescription}")
        }else {
            checkIsAppInstalledJobId = result.jobID
        }
    }
}

Here, we parsed the CallResult and put the id of this task in checkIsAppInstalledJobId. When the call fails, we print its reason.

5. Handle Api call results.#

Since DeviceManagerService API are all asynchronous calls, therefore, after asynchronous completion, the interface in IDeviceManagerResultListener registered in DeviceManagerSerice will be triggered:

fun onResult(jobId: Int, result: String?) {
    Log.d(TAG, "on job done ${jobId}, result $result")
}

The result is:

class ApiFinishedResult {
    /** The completed jobId */
    var jobId = 0
    /** Completion situation, 0 call succeeded, -1 the task was cancelled, -2 failed */
    var returnCode = 0
    /** Api call result, determined by the specific Api called, corresponding to the Result in the Api document */
    var result: String? = null
    /** When the task fails, record the cause of the failure */
    var error: String? = null
}

The serialized result.

Here, we still use the example in the previous text to handle its Api call results. Here, we print it:

class CheckAppInstalledResult{
    var isExist : Boolean = false
}

class ApiFinishedResult {
    var jobId = 0
    var returnCode = 0
    var result: String? = null
    var error: String? = null
}

private val mResultListener: IDeviceManagerResultListener =
    object : IDeviceManagerResultListener.Stub() {
        override fun onResult(jobId: Int, result: String?) {
            val apiResult = Gson().fromJson(
                result,
                ApiFinishedResult::class.java
            )
            if(jobId == checkIsAppInstalledJobId){
                if(apiResult.returnCode == 0){
                    Log.i(TAG,"check is app install successed")
                    val result = Gson().fromJson(apiResult.result,CheckAppInstalledResult::class.java)
                    Log.d(TAG,"Is apk installed result :" + result.isExist);
                }else{
                    Log.e(TAG,"Failed , reason : ${apiResult.error}")
                }
            }
        }
    }

6. Handle events (Event).#

When an Event is triggered, the interface in IDeviceManagerEventListener registered in DeviceManagerSerice will be triggered:

fun onEvent(eventType: String, eventInfo: String?)

The definitions of eventType and eventInfo can be viewed in the Events

Here, suppose we want to listen to the WIFI_SCAN_RESULT event and output the result, it can be achieved through the following code:

private val EVENT_TYPE_WIFI_SCAN_RESULT = "wifi_scan_result"

class WifiScanResultEvent {
    var results: List<WifiScanResult>? = null
}

private val mEventListener: IDeviceManagerEventListener =
    object : IDeviceManagerEventListener.Stub() {
        override fun onEvent(eventType: String, eventInfo: String?) {
            if (eventType == EVENT_TYPE_WIFI_SCAN_RESULT) {
                val result = Gson().fromJson(
                    eventInfo,
                    WifiScanResultEvent::class.java
                )?.results?.also {
                    it.forEach { wifiScanResult ->
                        Log.d(TAG, "On wifi scan result: $wifiScanResult")
                    }
                }
            }
        }
    }
