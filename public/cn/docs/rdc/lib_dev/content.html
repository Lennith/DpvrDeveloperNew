内容分发与下载¶

服务端通过 RDC 内容清单消息通知设备下载资源。RDC 负责传输清单和回传状态，不负责提供资源文件；资源文件需要部署在设备可访问的 HTTP/HTTPS 服务上。

服务端发送内容清单¶

服务端库提供以下两个接口：

public void SendContentList(string sn, List<Message.ContentItem> contents)
public void SendContentListToClients(List<Message.ContentItem> contents, List<Client> clientList = null)

SendContentList 根据 SN 发送给单个已连接客户端；SendContentListToClients 在 clientList 为 null 时发送给所有客户端。

内容项结构：

public class Message.ContentItem
{
    public string content_id;
    public string file_name;
    public string url;
    public long size;
    public string hash;
    public string version;
}

content_id 是客户端建立任务和关联状态的唯一标识，缺少该字段的内容项会被客户端忽略。file_name 也是必填字段，允许使用 UTF-8 文件名（包括中文），但只能填写单个文件名，不能包含 /、\、%、?、# 或 .. 等路径片段。

url 必填且必须使用 HTTP/HTTPS，并会原样传给设备端下载服务。请将资源部署为设备可访问的静态地址，例如：

http://192.168.1.100/dpvr/content/demo.mp4

可以使用 Nginx 或 Windows 自带的 IIS/HTTP 服务提供该目录。测试前应确认设备能够直接访问 URL，并且 HTTP 服务允许设备所在网络访问；RDC 服务端不会代理或托管该文件。

设备端下载流程¶

客户端收到 4001 内容清单后，当前实现会：

  1. 为每个具有有效 content_id、file_name 和 url 的内容项调用 ContentDownloadManager.addContentTask。

  2. 通过外部组件 com.dpvr.downloadmanager/.DownloadService 绑定 DPDownloadService。

  3. 使用 IDownloadManager.addTaskSimple(url, PRIORITY_SYSTEM, "contents/<file_name>", true) 创建任务，自动开始下载。

  4. DownloadService 通过 Android DownloadManager 将文件写入系统公共下载目录的 contents 子目录，典型路径为 /storage/emulated/0/Download/contents/<file_name>。

下载服务使用 Android DownloadManager.Request(Uri.parse(downloadUri)) 和 setDestinationInExternalPublicDir(Environment.DIRECTORY_DOWNLOADS, downloadFilePath)；应用已显式允许 HTTP 明文下载，因此资源可使用设备可访问的 HTTP/HTTPS URL。RDC 客户端不添加或实现 DownloadService 入口，只使用其现有 IDownloadManager AIDL 封装；不需要在 RDC 工程中新增 IDownloadService.aidl。

兼容性要求：设备固件中的 DPDownloadService 必须支持上述公共 Download/contents 目标目录和 HTTP/HTTPS 下载。旧 alpha 实现使用空目录类型，文件会写入外部存储根目录而不是公共 Download 目录，与当前 RDC 路径约定不兼容；提测文件部署前需要更新该系统服务。

当前 RDC 客户端使用的下载 AIDL 方法包括：

int addTaskSimple(String uri, int priority, String downloadFilePath, boolean autoStart);
int startTaskById(int taskId);
void stopTaskById(int taskId);
void removeTaskDownloadFileById(int taskId);
void registDownloadStateListener(IDownloadStateListener listener);
void unregistDownloadStateListener();

DownloadTask 的跨进程 Parcelable 顺序为 taskid、downloadUri、priority、downloadFilePath、autoStart；服务包名相同不代表可以混用不同历史 AIDL 或 Parcelable 定义。

一次性执行语义¶

4001 内容清单是一次性的执行指令，不是服务端持久化的待执行队列：服务端下发一次，设备端收到后执行一次，并通过 4002 上报当前状态。TCP/Wi-Fi 断开、设备重连或心跳超时不会触发 RDC 自动重新发送 4001；设备端也不会因为连接恢复而自动新增或重试任务。需要重新执行下载时，服务端必须显式再次下发对应的 4001 内容项。同一 content_id 再次下发表示重新执行，RDC 调用方会通过 Binder 移除旧任务及文件后创建新任务；不承诺自动重试或断点续传。

状态上报¶

客户端通过 4002 消息上报内容状态，每 2 个心跳发送一次；心跳周期为 2 秒。contents 是当前设备记录的完整快照而不是增量；即使没有内容条目也会发送空数组，服务端应使用快照替换旧记录。

{
  "sn": "设备序列号",
  "contents": [
    {
      "content_id": "demo-video",
      "status": "downloading",
      "progress": 42,
      "downloaded": 0,
      "local_path": "file:///storage/emulated/0/Download/contents/demo.mp4",
      "error": null
    }
  ]
}

status 当前映射为 pending、downloading、waiting、finished、idle 或 error；progress 是百分比；local_path 来自 DownloadService 的本地路径。进度回调不会覆盖当前状态；DownloadService 报告错误状态且没有更具体错误时，调用方会使用 download_failed。当前 ContentManager 不主动计算 downloaded 或校验 hash；创建任务前的校验或调用失败时，error 可能为 invalid_file_name、invalid_url 或 download_task_create_failed。下载服务不负责上层超时、重试或续传策略，Binder 调用方应自行处理。

finished 只表示 DownloadService/Android DownloadManager 已报告该任务成功，也不代表已执行 hash 校验。RDC 客户端生成 4002 快照时会检查 local_path；如果已完成文件被外部删除，则从快照中移除该条目并由服务端清除对应记录，但不会自动重新下载。需要重新部署或补齐文件时，应由服务端显式再次下发对应的 4001 内容项。
