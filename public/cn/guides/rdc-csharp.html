用 C# 建立一个 RDC 控制端

先让一台头显连接并上报身份，再发送单设备指令、检查实际状态。

准备条件

  • 准备 Windows 64 位 .NET 7 开发环境及官方 RDC 库或示例。
  • 准备支持头显与同一局域网；USB/adb 用于检查系统包，不是 RDC 正式连接通道。
01

核对设备端服务

第一条应输出 com.deepoon.eggchair；缺少时按文档检查系统版本。只有要控制视频或开机自启时才分别要求后两项。看到必要包后再进行网络配置，电脑 DLL 不能补齐头显系统服务。

adb shell pm list packages com.deepoon.eggchair
adb shell pm list packages com.dpvr.videoplayer
adb shell pm list packages com.dpvr.daemonservice
阅读：核对设备端服务 →
02

设置网络与设备连接目标

初次可手填控制端局域网 IP 和端口；保证控制端监听该地址且设备可达。选择 AUTO FIND 时，控制端还须开启发现功能、双方同一广播域且路由器允许广播；启用后手填地址不生效，同名 Wi-Fi 不保证满足条件。

阅读：设置网络与设备连接目标 →
03

选择匹配的 C# 库

使用当前在线文档链接的 .NET 7 Win64 库与示例，引用 DPVR 命名空间。目标电脑缺少 .NET 7 Runtime 时核对附运行时包。先让项目成功编译，不要混入旧归档中的同名 DLL。

阅读：选择匹配的 C# 库 →
04

先注册监听再启动服务器

片段需放在已引用官方库的应用中，并保持 mServer 存活。回调 state=1 表示已连接且设备已上报 SN；打印 SN/IP 后再启用指令。Start 默认端口 10086，要与设备设置一致。

var mServer = new DPVR.DpvrRDCServer();
mServer.OnConnectStateChangedEvent += (client, state) =>
    System.Console.WriteLine($"state={state} SN={client.SN} IP={client.IP}");
mServer.OnMessageEvent += (client, message) =>
    System.Console.WriteLine($"SN={client.SN} from={message.fromPackage}: {message.content}");
mServer.Start();
阅读：先注册监听再启动服务器 →
05

明确目标后发送一条指令

以下为控制台局部片段，与上一步使用同一个存活的 mServer。输入连接回调已经打印的头显 SN；仅在找到客户端且 ConnectState=1 时发音量指令。显式传单设备列表，避免省略目标而作用于全部设备。实际音量变化留到下一步核对。

System.Console.WriteLine("Enter the connected headset SN:");
var targetSerialNo = System.Console.ReadLine();
var client = string.IsNullOrWhiteSpace(targetSerialNo)
    ? null : mServer.GetClient(targetSerialNo);
if (client != null && client.ConnectState == 1)
{
    mServer.DeviceSetVolume(20,
        new System.Collections.Generic.List<DPVR.DpvrRDCServer.Client> { client });
}
阅读：明确目标后发送一条指令 →
06

检查状态再扩展业务

读取客户端的 SN、IP、ConnectState、电量和前台应用，确认心跳状态持续更新，并在测试头显核对音量实际变化；这些状态不等于逐条命令成功应答。断连先查地址、端口和网络。以后做 HTTP 内容分发还须独立托管文件：RDC 只发送清单，设备 DownloadService 才下载文件。

阅读：检查状态再扩展业务 →
本路线先验证连接、状态与单设备控制；不把发送成功当执行完成，也不把默认 maxClient=64 当性能保证。多设备同步和 HTTP 分发需再读专门章节。
