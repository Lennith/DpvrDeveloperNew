# 信息架构与任务验收

## 选择原则

首页提供“管理现有设备 / 开发应用与控制端 / 部署视频体验”任务捷径，但它们不是互斥目录。全部10项资源始终可发现，型号筛选只缩小官网声明的适用范围，不替用户断言新版更合适。每项资源只有一个概览，说明实际用途、条件、步骤和对应下载。

产品概览 → 有来源的操作/接入步骤 → 当前技术原文与接口参考。阅读器只显示当前产品的导航，默认展开当前分支；语言切换保持同篇。中文默认，英文独立完整页面。当前Release Note保留，旧DM/RDC快照不进入站点。GUI/CLI是工作方式，不做历史版本分类；手势只有当前入门和参数参考。

## 独立UX审查后的调整

- 任务分类互相重叠，因此作为捷径而非强制分流；选P2后GO与GO2都保留，明确能力和资料边界。
- DMS先选Android/Unity，再读该栈前置；明确NORMAL无需额外Key，不能让所有新手先申请授权。
- RDC先解释控制端与头显端角色，再选择C#库或协议路线。
- 投屏按接收端能力分支，不能让用户把Miracast和DPVR Wi-Fi步骤都做一遍。
- 产品资料不足时不套模板编造教程；已核实步骤与尚未说明的条件分开。

## 真实任务与成功判据

1. P2运营人员管理设备：主页设备筛选 → 比较GO/GO2用途 → 进入适合的概览 → 找到官方对应下载。不得误导GO已停用或必须开发SDK。
2. Android应用获取设备状态：DMS概览 → Android入门 → 服务/权限/回调 → 查API的Permission/Params/Result；理解任务受理与完成不同，能找到失败排查和同文英文。
3. 控制多台头显：RDC概览 → 设备服务/网络前提 → C#库或协议 → 初始化与连接 → 具体控制。不得先向新手展开全部协议细节。
4. 让设备启动播放指定视频：播放配置概览/部署引导 → 路径与模式 → 配置放置位置 → 原字段参考；加密和TF部署明确为按需分支，不强加为必需步骤。
5. Unity手势首接：确认P1 Pro 4K Camera → Android真机和渲染前置 → SampleScene → 预期交互 → 按症状排错 → 参数。不能把球体示例宣称为精确3D手追。

## 验收

先检查首页、DMS入门/API及视频部署引导的桌面和手机真实浏览器体验，再生成全部内容。核对任务是否可完成、下一步是否明确、目录是否聚焦、移动阅读和语言切换是否有效；另做源正文/代码/图表/链接保真检查。网站测试不代替SDK或头显实机测试。
