# 缺陷与修复记录 · 2026-10-01

| 问题 | 根因 / 证据 | 修复与回归 |
|---|---|---|
| 双击 HTML 无样式、深层链接失效 | 旧生成器把 href/src 写成 `/assets/…`、`/cn/…`，file URL 会解析到磁盘根；子目录也会逃出部署前缀 | 根据每个输出 HTML 的目录生成相对地址；根入口单独生成，不能复制已经相对化的 cn/index；全量本地文件/大小写/锚点解析及两种 HTTP 路径回归 |
| 搜索和旧 hash 仍跳到网站根 | JS 直接拼接 BASE 或 `/cn/…` | 每页 data-root 定位交付目录；搜索/查询页和旧 hash 按目录解析；10 个旧入口逐个测试 |
| Playback 标题错误暗示头显开机自启 | 整理教程标题写“让头显启动后播放” | 改“让系统播放器启动时播放”；明确不负责开机启动播放器；中英文正文和搜索更新 |
| 手势动作对应关系不完整 | 操作引导只有标识符列表 | 增补实体手势—标识符—预期结果四行表，含一次性定位、放大、缩小、换色；不是连续手追踪 |
| TF 与播放器任务之间需要自行拼接 | 缺少同页 TF 目录树和 FILE 任务示例 | 新增已验证视频/配置的 TF 部署步骤、完整 JSON、目标路径检查与播放器验证；注明 P1 Max 不支持 |
| 首页层次重复、卡片过多 | 任务快捷卡片和产品卡片重复列相同内容 | 三个任务区连续列表，每产品一个概览；用途/人群/运行位置/条件可直接读到；去掉侧栏重复型号/边界卡片 |
| 图片无法放大 | app.js 未实现放大控件 | 增补本地图像 dialog、键盘打开、Escape 关闭及焦点恢复 |
| 复制代码在无 Clipboard API 时不可用 | 仅尝试 navigator.clipboard | 增补临时文本框复制回退，失败仍明确提示手动复制；HTTP 回归确认“已复制” |
| 两份加密 runtime 目录没有 h1 | 原文目录仅含链接 | 增补标记为整理内容的导航标题；原目录全文不变 |
| 源码片段被误当网站入口的风险 | 源码包与public并列，打开content/articles会无样式；不推断用户实际打开方式 | 静态站点与源码拆成两个ZIP；静态包根层即index.html；源码包醒目标明片段非入口 |
| 12页重复锚点ID | 原文在嵌套span/table上重复id；浏览器默认命中第一个 | 生成时保留首次出现的目标，移除后续同名id；源文不改，目标语义不变；审计新增重复ID失败项 |
| GO手册来源入口遗漏 | stephtml只读取docMatch，GO步骤仅有source | 回退读取source，完整官方PDF及页码入口可访问；PDF未随当前授权恢复包提供，未伪称完成整本离线复核 |
| TF 原文数字与默认项目符号重复 | 原 HTML 使用 manual-steps，但统一 CSS 未适配 | 保留源文本，把数字与段落同行排布；调整章节编号，复查桌面手机截图 |

没有确认的外链 404：506 个唯一外部地址实际发起 GET（只读取小段内容），全部被本环境代理拒绝，均记 UNVERIFIED_NETWORK，不能据此改写或删除官方下载。SDK 大文件没有打包进网站。

测试脚本自身也修正了三项误判：空的图片放大占位图不应算损坏资源；HTTP 304 不强求重发 MIME 头；被策略拒绝的 file 导航使用独立标签页，避免污染后续 HTTP 测试。复制按钮需等待异步完成。以上没有用排除真实失败的方式改变页面验收标准。
